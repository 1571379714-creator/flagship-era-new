# 旗舰元年 5.3 → 6.0：结构重构与交付检查

6.0 产品平台与开放市场 · 2026年9月21日 · 首测版

## 1. 版本边界

依据用户对彻底重构的授权，继承5.3实际数据以及改造前原版的供应链、单机技术配置、有限市场与库存主题。本版不是5.3补丁，旧企划、企业、项目及行动卡不能混用。原5.3交付文件未覆盖。本轮未向GitHub推送，未改变远端main、VERSION或v5.0；本地文件存在不等于仓库已经更新。

明确保留的要求：收入与科技是可选择的两条主线；卡牌内容多样；共同发布只由玩家主动推进，不设固定轮数；参考机从可能出现的不同机型中随机抽取，弱项奖励少或没有，强项奖励多。

## 2. 结构变化

| 5.3 | 6.0 |
|---|---|
| 五行动强度1—5轮转 | 每个本人回合3工作点，自主组织采购、研发、定型、生产、合同和设施 |
| 双轨相遇，收入与科技加总 | 收入60或科技30分别触发；最后按收入与2×科技的较大值比较 |
| P企划决定能造哪类手机并印收入 | 四部件直接定型，Q产品方案可选；收入须实际成交或完成明确成果 |
| 稳定件发布后归库，旧机只存数字 | 部件与部署技术占用到型号退市，真实库存可以留到下次销售 |
| 每公司每市场只取最强代表 | 所有投放型号竞争有限订单；同批库存不可跨市场重用 |
| 公司图标积累、公共项目档位 | 有工期与样机证据的研发、有限期合同、付费空间设施 |
| 通用正常回款 | 删除；运营现金来自真实销售、合同、技术服务及有限回收 |

60/30门槛、3工作点和科技成绩系数2属于本版首测值，不是用户指定参数，也不是恢复固定五倍科技相加的旧模型。科技栏仍印到36，并允许越界；不要求正常对局走满。

## 3. 主动共同发布

每人每回合可花1工作点预热一次，自选推进1—3格。两人终点12，三人16，四人20；没有行动自动推轨，没有固定销售季或全桌一圈必结算。到顶后当前玩家做完剩余工作，立即共同发布，其余玩家没有响应回合。

供货世代由首位科技达到3/7/13/20解锁，与发布次数独立。新代供货在回合末处理，但不替换已公开的当前参考机和需求。普通发布结束先处理应开放的供货，合并一次维护，再为下一准备期抽取需求与当前代参考机。最后阶段每人仍有一个完整回合，只在全部完成后统一最终发布。

## 4. 随机参考机与奖励

共30款V参考：五代，每代六个定位，包含基础通信、均衡主流、电竞、影像、商务折叠与全能旗舰。一次抽1张全桌共用，四市场数值印在同一张上；不是每市场独立造一个机器人。

参考机准备期开始就公开，持有至实际发布结束。在每市场参与分配，最多取得1份订单，没有资金、生产或自动行动。参考竞争值已抽象其定位，不再跟随玩家的价格、偏好或年龄修正。真人同分优先成交，但挑战奖励要求严格超过。

| 被击败的实际市场格数值 | 星级 | 一次完整奖励二选一 |
|---|---|---|
| 至多10 | 0 | 无 |
| 11—16 | 1 | 2收入或1科技 |
| 17—24 | 2 | 4收入或2科技 |
| 25以上 | 3 | 6收入或3科技 |

必须在该市场至少真实零售成交1批；每公司每场最多领取一份。科技奖励另外要求该型号本场首发，并部署至少一项已经完成的研发。旧型号可以拿收入挑战奖，不能靠反复清仓刷科技。不能击败摄影弱项而领取电竞强项奖励，合同、残值和没有成交的理论分数不算挑战。

## 5. 生产、价格与研发的落实

取得稳定供货资格与逐批制造分开付费。每实际芯片平台通常每周期2批、全公司通常6批；只记录芯片配额，不给四类部件再分别开数量台账。T37共用平台的两个型号共享同一个实际芯片用量；退市再定型也不会刷新已用配额。公司产能最高10，每型号库存通常4、扩容最高8。

售价为18/28/38/48，竞争修正为+6/+2/−2/−6，实际每批成交收入为1/2/3/4。生产先付款，成交收实际售价，没有订单就保留真实库存；不能用尚未到账的销售款制造本批货。四市场需求会交叉，一台机可分配真实库存到多个合格市场。型号首发年龄0，之后1、2，再退市；T16有明确延寿例外。普通回收每批3现金，特例按卡面，没有无库存清仓奖励。

研发T有费用、工期、前置、证据、成果与部署/工艺权限。技术服务和验证合同为研究路线提供不要求大量销量的现金入口；工期或样机未通过不能领奖。独立验证每型号一次、每公司每发布周期一次。设施占空间，合同有期限与承诺，可选产品方案不作为造机许可。

## 7. 本轮实际执行与未执行

- 数据/规则检查：6323项断言通过。其中1200个独立单市场情境与另一套逐批排序法对照，覆盖2—4人、预算、真实库存、并列、有限订单和参考奖励。不是1200局游戏。
- 文件与排版检查：4397项通过，全部PDF逐页解码、页面文字边界；243种卡名、ID与完整效果在索引指定PDF页出现，HTML各卡无检测到的效果/页脚重叠。基础字段由同一JSON生成，不将自动生成本身当作第二套独立规则验证。
- Word正文13页、规划5页使用规范渲染脚本出图后逐页检查；图鉴47页完成总览及五张重点牌放大检查；8个版图全视图、实体7张版面完成检查。图鉴总览不等于逐字放大，另有文字检查。
- 价格正反面按型号行核对，横向镜像最大软件误差约0.021毫米。仅为浏览器几何，不是实际打印机套准保证。
- 科技36仅验证给定状态下的29→30触发、额外回合到33、最终合格挑战到36的边界。没有执行一条从开局开始、含真实取得牌序和现金的完整36科技对局。

另在独立目录删除所有生成成品后，只从当前JSON/Markdown重新运行build_all.py，重建后的全部HTML字节内容相同，全部PDF页数及逐页文字相同；PDF内部时间/元数据使二进制不一定相同。记录见work/rebuild_verification_v60.json。

没有全卡特效解释器、全部联动穷举、隐藏信息智能对手、真人胜率或充分多人实桌测试。不是已平衡、不是90—150分钟实测证据。numeric_core.py是有限生产/单市场模型，不提供电子游玩。

## 8. 实体准备与输出

价格组件每人16张，对应型号1—4，各有四种售价。实体PDF第1—2页A4原尺寸、长边翻转双面；其余单面。先试印，不能保证设备套准。第3页每人一张秘密投放；第4页每人一张型号状态；第5页可裁开平台用量条放到实际芯片；第6页按需准备标记；第7页全桌速查。编号、年龄、库存和投放用现成方块或附带指示片，不用纸笔。

型号开发版图每人按需准备四份或在桌旁按相同结构排列卡片；一份是一个型号，不是每人只准一个型号。参考机V与需求N从全卡图鉴按编号准备。图鉴为完整参考卡面，不是统一卡背、出血刀模齐备的量产文件。HTML只有查阅、视图切换与打印，无联网、发牌、自动结算或存局。
