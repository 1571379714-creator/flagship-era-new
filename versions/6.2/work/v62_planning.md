# 旗舰元年6.2 设计规划

## 01 本轮已确认的目标
减少维护牌堆、补牌、搬配件和记录产品历史的操作。以用户实际收到的6.1为唯一底稿，不回到5.x，不改为固定轮数。收入与科技仍是可选主线，参考机仍在锁定后当场随机揭晓。

用户确认四个关键边界：新稳定顶掉同类旧稳定；只有最后一个产品引用结束才解除锁定；参考机与需求保留功能牌堆；“可以取消令配件回到手中”是允许取消已生产的产品并回收配件，不是禁止回手。进一步接受未售货跨场原样等待，但不管理老机型或代龄。

## 02 统一牌流，不让简化只停在地图上
主牌257张从开局全部混洗，不再按五代分别放货。公开区只保留8张牌市。每个工作取至多2张，整次工作选完再补空位；普通发布只做一次弃最左2张、左移、补满。新世代只移动开放标记。

原6.1有稳定四类、定制、研发、商业等多个可采购陈列。单一牌堆会削弱定向取得，这是本版最主要的新代价。通过保留8张公开选择、一次取2、起始四类稳定保底和受限筛牌设施缓和，而不是暗中额外开研发牌市。

未来部件可以提前拿或付费入库，但不能用于组装或样机。提前占住库栏会暂时失去该类稳定供货，可以改用当前世代定制，或在无引用时再替换。规则不帮玩家无成本保留第二套旧平台。

## 03 四栏库与产品位是两种不同空间
稳定库四栏表示公司当前选择的供货方案；手牌中的其他稳定只是尚未安装的候选，不是可以直接造机的备用库。拿牌不收取得费，入库时付印刷费。当前把非初始入库费统一写9，不随代差折价。

产品使用“稳定部件·种类”代替卡。真实稳定卡不离库，同一栏可供应多批，每批仍付制造费。任何现存引用都锁定该栏，这避免换一张芯片让过去生产的货全部凭空升级。

无需锁定计数器：代替卡已经承担这个作用。发布中的成交产品保留配置到所有奖励结算完，防止在结算半途换库或释放技术改变结果。

## 04 取消两层库存，保留真实投资风险
每产品位＝一批已经付款的现货。组装1工作点，直接做1批。想再做相同配置需要另一个产品位、另一个组装工作并重新付款；稳定可以引用，定制和部署需要独立实体。取消平台配额、公司产能和每型号库存条。

合并后的组装费8对应旧开发费6加装配费2。部件费与方案费继续在卡上。没有对所有配件数值做全套放大或重平衡；此值只是第一批沿用经济尺度的首测选择。

取消免费，但不退款。定制与Q回手，技术释放，代替卡收回。未售货可以留存；成交货消耗定制与Q并释放产品位。Q21是方案回手的明确例外。没有免费残值、到龄报废或自动库存折价。

改款就是取消后重新组装。T31/U14可以降低紧接的改款费用，省掉重复规则，而不允许锁定后临时改机。工作或现金不足时先取消的决定不会自动撤回。

## 05 每一类受影响卡牌都要改变接口
| 旧能力依赖 | 6.2处理 |
| --- | --- |
| 特别允许共用芯片 | 共享已为基础，T37改同平台组装优惠，C07改稳定屏幕适配。 |
| 一次生产多批、库存容量 | T13改产品能力，U01/U02改安装协同／专用单批工作，U13改手牌容量。 |
| 同型号交两批 | H01—H15由多产品位一次交齐，每批逐一合格，允许配置不同。 |
| 同一型号跨市场 | T29/Q11/Q24改为多个实际产品的跨市场协同。 |
| 首发、代龄、延寿 | 删除历史依赖；T16/T36/T40和H26/H29等重新设置当下状态条件。 |
| 成熟代差降价 | 删除通用折价，具体优惠在C03/Q02等本卡写明且不依赖年限。 |
| 取得配件付费 | 一律免费入手；供货引荐改入库券，旧供应采购能力改统一牌流或安装。 |
| 每型号一生验证一次 | 改为公司当前世代验证格，取消/重组不复位，免记历史型号。 |

卡片编号、份数与部件基础规格保留，研发与订单主要经济数值沿用。全套仍243种、315张。没有为了凑数量把失去作用的配额卡原样留下。

## 06 参考机与无纸笔操作
V仍每代6张，锁定后现抽、每次全部放回。需求始终预先公开。挑战要真实零售成交且严格超过实际市场格；科技/工程试验只查该批锁定时是否部署完成研发，不再区分首发。成交即结束的批次不会反复领奖。

三类留存奖励各至多一件：推荐章、入库券、单批试产券。试产始终只造1批，星级体现为现金优惠，不再印1/2/3批。不会在发布时临时补货。

一个产品号去向片表示一批，合同或市场只能选一处。已售／已收款状态保留现场证据，结束后统一清空。不再需要32枚库存块、平台用量条或代龄条；用真实押金、项目进度与期限片表示其他状态。

## 07 验证计划与不应宣称的结论
先测未来卡滞手与公开牌市的选择性；再测4产品位的实际成交密度，库栏锁定是否促进升级窗口，取消是否频繁到变成重复劳动；最后比较科技与收入的推进速度。

建议2人、3人、4人各至少做多次真实对局，记录每场实际批数、因锁定取消的次数、现金不足、参考奖种类和发布整理时间。收入60／科技30不在本轮随意同时调整，若单批化导致商业主线明显放慢，再依据对局数据修改。

程序测试只能验证具体状态转移、预算与订单计算、卡面一致性和文件完整性，不能证明所有特效组合已经平衡。本轮没有真人隐藏信息策略代理，也不保证90—150分钟实际时长。

## 08 版本与交付边界
本版从6.1实际数据生成，旧档案不覆盖。主牌与规则同时更新，不能把旧多批、首发、年龄卡文混进来。规则正文维持易读语言与侧栏，规划只解释设计，不增设隐藏规则。

本轮未向GitHub推送或修改远端。若随后归档，应另加versions/6.2，连同VERSION、README和协作说明一起更新；不要修改6.0/6.1原始快照。没有引入电子游玩、自动发牌或对局存档功能。
